# CleverHand — agent & contributor guide

CleverHand is an open-source modular hardware–software platform for HMI: biosignal
acquisition (EMG, ECG, ...) and sensory feedback (electrotactile, vibrotactile, visual).
This fork (**CleverHand-python**) reimplements the host stack in pure Python: the `clvhd`
driver in [`software/driver/CleverHand-interface`](software/driver/CleverHand-interface)
replaces the former C++ driver for the 13-module EMG wristband (Teensy 4.0 controller +
ADS1293 modules). Hardware designs live in `hardware/` (KiCad); the older inter-module
firmware in `software/firmware/`.

This file is the entry point for anyone (or any agent) working in this repository: a
documentation map, the layout, the commands to run, test and lint, and the rules every
change follows. The Python driver has its own
[AGENTS.md](software/driver/CleverHand-interface/AGENTS.md) with its conventions — read it
before editing there. Note: some files under `docs/` (e.g. `docs/flashing.md`,
`docs/*plan*`) are working docs kept local and git-ignored; links to them only resolve on the
author's machine.

## Environment & tooling (driver)

Everything in `software/driver/CleverHand-interface` runs through
[uv](https://docs.astral.sh/uv/) (`uv run …`; nothing to activate):

```bash
cd software/driver/CleverHand-interface
uv sync --all-extras     # locked .venv (Python 3.13 from .python-version, uv.lock)
```

`uv.lock` is committed: after editing dependencies in `pyproject.toml`, run `uv lock` and
commit both. Don't hand-edit it.

## Run (with the wristband plugged in)

```bash
uv run clvhd-check                       # bring-up checks
uv run examples/01_live_plot.py          # live plot + Record to BIDS
```

## Test & lint (driver)

```bash
uv run pytest                                          # full suite (simulated Teensy, no hardware needed)
uv run ruff check . && uv run ruff format .            # lint + format
uv run mypy                                            # types over clvhd/, examples/, tests/
```

## Rules for every change

- **Simplest change that works.** Fix in place; no new abstractions, options or guard tests
  beyond what the change needs.
- **Same concept, same name** across modules and across the host/firmware boundary (module
  index vs bus address, `t_host`/`t_device`, frame constants). Grep before naming; the wire
  protocol's terms are fixed in `docs/serial_protocol.md`.
- **Short docstrings; comments say only what the code can't** (a spec rule, a unit fact, an
  ordering constraint, why a constant has its value). Experiment rationale lives in
  `docs/experiments.md`, not in module docstrings.
- **Change both sides of a contract together.** The serial protocol is shared by
  `clvhd/protocol.py`, `firmware/uctrl_teensy/`, `tests/_teensy_sim.py` and
  `docs/serial_protocol.md`: edit all four in one change. BIDS file layouts are shared by
  `clvhd/bids.py`, the examples and the tests.
- **Never touch** recordings under `data/`, `.venv/`, or hand-edit `uv.lock` (run
  `uv lock`). Hardware files are KiCad; don't reformat them with editor settings.
- **No new dependencies without asking.** The core driver needs only `numpy` and `pyserial`;
  `plot`/`hand`/`bids` are optional extras, imported lazily inside functions.
- **User-facing text**: console messages and docs are English, plain sentences that say what
  happened and what to do next; error messages reach users verbatim (no internals or
  tracebacks). The participant-facing screens of examples 02/03/04 are French on purpose.

## Commits

- Subject: imperative, with the area prefix used in this repo's history (`driver:`, `feat:`,
  `chore:`), no full stop. Join two changes with ", and".
- Body: prose saying what changed and why, wrapped at ~72 columns.
- One logical change per commit, with its docs and tests.

## Glossary

Use these terms in code, UI text and docs alike.

| Term | Meaning | In code |
|---|---|---|
| module | one board in the chain (COM_MOD + ADS1293 + electrodes), indexed from 0; its bus address is index + 1 | `m`, `nb_modules`, `mask` (bit `i` = module `i`; only for modules) |
| channel | one of a module's 3 bipolar channels: `ch` 0-2 within the module, `c = 3 * m + ch` across the wristband; labelled `m0_ch1` in files, `M0` / `ch1` on screen | `ch`, `c`, `Stream.channel_labels` |
| wristband | the Teensy 4.0 controller chained to the modules | `Wristband` (`wb`) |
| configuration | the ADS1293 settings of every module | `ads1293.Config` (`cfg`; `Wristband.config`) |
| frame | one 22-byte streamed sample of one module. Two other frames, always qualified: the **task frame** (one 60 Hz step of 03/04, `FRAME_RATE`) and the **camera frame** (`hand.HandFrame`) | `FRAME_SIZE`, `FRAME_SYNC` |
| sample | one aligned row of every channel, in V | `data` (samples × channels) |
| `t_host` / `t_device` | sample time on `time.monotonic()` / on the Teensy's `micros()` | `Stream.read()` returns `(t_host, t_device, data)` |
| time names | `t_<moment>` for an instant (`t_start`, `t_end`, `t_last`, `t0`); `<scope>_t` for the time since a scope began (`phase_t`, `trial_t`) | |
| counts | `n_<things>` (`n_channels`, `n_trials`); the module count is always `nb_modules` | |
| sps / ODR | samples per second (the ADS1293 output data rate); the nominal rate, before the clock fit | `Config.odr()`, `Stream.nominal_rate`, `fs` in local code |
| envelope | rectified, low-passed EMG (mV) at the 60 Hz task-frame rate | `coadapt.Envelope`; `u` one frame (channels,), `U` frames × channels |
| contact status | per channel: `""`, `"flat"`, `"poor contact"`, `"no data"` | `check_contact` |
| recording | one BIDS run: `emg/`, optional `motion/`, `beh/`, `_events.tsv`, in `sourcedata/` until exported | `bids.Entities` (`ent`), `RawRecording` (`raw`) |
| decoder | the cursor's linear map from EMG features to velocity (cm/s): a Wiener filter; its weights `D` (2 × features), `D0` the calibration's fit, `D*` a 20 s refit | `decoder.WienerFilter` (`wf`), `D`, `D0`, `D_star`; in files `decoder_file` (its .npz), `decoder_index` (the one in use: 0 the calibration's, k after the k-th update) |
| features | a decoder's input `x`: log envelopes, z-scored, over the last `LAGS` frames, plus a constant | `WienerFilter.push(u)` |
| cursor task terms | target `tau`, cursor `y`, velocity `v` (cm, cm/s; paper notation); calibration frames used in the fit: `in_fit` | |
| phase / trial / block | 03 runs a calibration and a test **phase** (`acq-calib`, `acq-online`); 04 runs **trials** in **blocks** (each condition once per block), each ending with the **probe** | `phase`, `trial`, `PROBE_S` |
| cue / go | a cued movement: in 02 the gesture card shown in grey (cue), then lit (go: move once); in 03's calibration a target lit while the guide cursor travels to it | `clvhd.cues`, `trial_type` `"cue"` / `"go"` |

## Before you finish

1. `uv run ruff check . && uv run ruff format .` and `uv run mypy` (in the driver folder)
2. `uv run pytest` (or the files for the area you touched)
3. Docs: update the one home of anything you changed (see the map above), in the same commit.

## Documentation conventions

- **One home per fact.** Driver usage → the driver README; wire protocol →
  `docs/serial_protocol.md`; experiment rationale → `docs/experiments.md`; code conventions →
  the driver `AGENTS.md`. Cross-link; never duplicate.
- **Tables are reference; prose is orientation.** `` `backticks` `` = a file path, CLI flag,
  BIDS entity or code identifier.
